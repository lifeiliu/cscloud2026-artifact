# E13 认证 fanout 补全实验结果

日期：2026-09-13。本地正式实验完成，所有预先声明的判定与状态检查通过。

本实验实现的是一个新增的 admission API：先调用现有完整 receipt/ancestry 验证器，再在同一 SQLite 事务中检查并提交认证限额、不同父子凭证边、nonce 绑定及终端提交记录。它直接复用现有 LL、Merkle、Signed-DAG 密码实现；未覆盖原验证器，也未把历史 B5 结果改名为新实验。

## 主结果：签名有效不等于符合数量策略

三种设计分别运行 seeds 17、29、43，限额 0、1、5、20，每个组合 10 组新序列。每组构造 limit+3 个签名有效的候选子凭证，随机排列提交顺序。每条输入同时进入密码验证对照和启用配额的 admission API。

| 设计 | 序列数 | 无配额对照：有效候选通过 | 配额内子凭证：应接受 / 实际接受 | 超额子凭证：应拒绝 / 实际拒绝 |
|---|---:|---:|---:|---:|
| Linked-List | 120 | 1,140 / 1,140 | 780 / 780 | 360 / 360 |
| Merkle | 120 | 1,140 / 1,140 | 780 / 780 | 360 / 360 |
| Signed-DAG | 120 | 1,140 / 1,140 | 780 / 780 | 360 / 360 |
| 合计 | 360 | 3,420 / 3,420 | 2,340 / 2,340 | 1,080 / 1,080 |

这里有 3,420 条不同候选输入、6,840 次配对验证调用。不能把同一输入的两个实验臂当成两个独立攻击样本。对照没有配额状态，也没有模拟 E13 的终端重放策略；它的用途只是确认这些超额凭证在密码学上有效。

在这组固定 conformance matrix 中，拒绝效果来自认证限额与状态执行；三个密码构造共享同一策略层，结果一致不构成 Signed-DAG 在 B5 上优于另外两种设计的证据。

## 状态与故障结果

| 检查 | 实际结果 |
|---|---|
| 签名限额篡改、无效主签名、替换输出、重新主签名但祖先关系错误 | 按预期在密码验证阶段拒绝 |
| 有效签名但负数、布尔、非整数限额 | 按预期拒绝；null 限额的合法请求接受 |
| 无效请求后重新提交合法子凭证 | 接受，配额未被先前失败消耗 |
| 多 hop 请求在后续父节点处超额 | 整个请求回滚，先前暂存的边和 nonce 不留在状态中 |
| 已提交节点后来作为历史祖先、不同路径复用相同祖先边 | 接受合法新子节点，不重复计数共享边 |
| 相同终端凭证再次提交、同一签署者将同一 nonce 用于不同凭证 | 分别以 terminal replay / nonce conflict 拒绝 |
| 不同父凭证复用同一 instance ID | 配额隔离；同签署者重新签发的新父凭证也属于新 scope |
| 已记录祖先的签署密钥被本地撤销 | 再次使用祖先时仍重新验证并拒绝 |
| 四个独立进程争抢最后一个配额 | 9 组竞争均恰好 1 个接受、3 个 fanout 拒绝 |
| 四个独立进程提交同一终端凭证 | 9 组竞争均恰好 1 个接受、3 个 replay 拒绝 |
| 新进程读取原数据库后重放终端凭证 | 9 组均拒绝 |
| 子进程在同一事务暂存三张状态表后被终止 | 9 组均恢复到先前已提交状态，随后合法写入成功 |

正式日志共 **7,173 条事件**：7,137 条串行调用、18 条进程竞争、9 条新进程重放、9 条中断写入恢复。竞争事件各含四次调用，因此事件数不是调用数，也不是独立攻击数。

所有 **1,233 条串行拒绝记录**的前后完整逻辑状态摘要一致；477 个结果数据库的 SQLite integrity check 均返回 `ok`。未出现预期判定不符或意外中止。故障实验覆盖显式未提交事务的进程中断，不代表验证了断电、磁盘损坏或整机崩溃。

原始计数来自 [outcomes.csv](results/formal_20260913/outcomes.csv)、[summary.json](results/formal_20260913/summary.json) 和 [独立日志计数检查](results/formal_20260913/independent_accounting.json)，不是用计划值代替实测值。

## 测试、重放与 provenance

- 21 项新增测试通过，包含跨进程配额竞争、重复提交和中断事务。
- 75 项现有相关回归测试通过：完整验证器、chain round-trip、原 ASR matrix。
- 小规模试运行：339 条事件通过，已完整重放。
- 正式运行实际耗时约 108.7 秒；这只是执行时间，不是协议延迟基准。
- 环境：Python 3.11.9，cryptography 48.0.1，SQLite 3.45.1。fixture 有效性时钟固定为 2026-09-13 12:00 UTC，并记录在配置中。
- seed 控制候选次序，密钥和 nonce 使用 OS 随机源；完整重放依靠归档的签名请求与公钥，不依靠重建私钥。
- 65 个源码/说明文件在正式运行前冻结并校验哈希。重放使用 `source_snapshot/e13/run.py`，避免后续仓库修改影响。

## 能支持和不能支持的论文表述

可以支持：在固定的三种 ancestry 构造和所测序列中，新增 admission API 验证父凭证中的签名限额，拒绝超过限额的新增子凭证；历史祖先复用、nonce 绑定、终端重放检查和配额更新在单个共享持久化 store 内一致执行。

不能支持：检测哪个 child 带有恶意意图、限制已经实际执行的工具调用、统计所有未呈现的子节点、跨独立数据库的全局限额、跨父凭证重新签发的累计限额，或生产系统的权限/密钥轮换正确性。

配额单位是 **不可变父凭证下的不同子凭证**，不是同一 agent instance 的永久限额。新父凭证可建立新 scope，这是已声明的实验边界，不应被省略。

可供后续论文修订采用的英文文字：

> We separately evaluate authenticated fanout admission using the complete receipt verifier and a transactional local SQLite store. Across three ancestry constructions, four limits, and 360 sequences, all 2,340 within-limit child presentations were admitted and all 1,080 overflow presentations were rejected. The cryptographic-only control accepted all 3,420 candidate presentations, isolating the effect of stateful policy enforcement. The limit applies to distinct child receipts under one immutable parent receipt observed by the same store; it is not a global limit on agent execution.

这组数据应作为新 E13 结果单独呈现。旧 3,000 次 B5 threshold checks 保留为历史记录；不要继续用原 Fig. 3 的 27,000 统一“invalid presentation rejection”口径，也不要把旧计数加进 E13 分母。

本轮完成设计、实现和运行实验；论文 PDF/正文尚未纳入新结果，审查项 M1 仍需在文稿同步后才能关闭。
